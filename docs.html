Install

Talk2Me is distributed as a signed APK from GitHub Releases. There is no Play Store listing and no account to create.

  1. Download Talk2Me-v1.0.apk (about 41 MB) on the phone.
  2. Open the downloaded file. If Android asks, allow your browser or file manager to install unknown apps.
  3. Confirm the install. On MIUI/HyperOS you may see an extra confirmation dialog; approve it.
  4. Open Talk2Me and allow the microphone permission.
  5. Allow notifications on Android 13+ so the ongoing-call controls are visible.

Upgrading from a debug build?

Debug and release builds use different signing keys, so Android refuses to update one over the other. Uninstall the old app first. That clears saved app data, including any TURN credentials.

Your first call

Both people open Talk2Me. One starts the call; everyone else joins with the same code. There is no ringing and no incoming-call screen.

  1. On the first phone, tap Start a call. An eight-character code appears, such as K7M2-XQ9F.
  2. Send that code to the other people. The copy button and Android share sheet are both fine.
  3. On each other phone, tap Join a call, type the code, and continue.
  4. Wait for the call screen. On the same Wi-Fi, audio usually starts within a few seconds.

While connected you can mute, switch between earpiece and speaker, and see a call timer. The ongoing notification also has Mute and End actions, so you can control the call without reopening the app.

Test on the same Wi-Fi first

If a call fails on the same network, the problem is not NAT. Test there before adding a relay so you know which variable changed.

Group behaviour

  • The room holds up to four people. A fifth phone sees “That call is already full (4 people max).”
  • Hanging up removes only that person; everyone else stays connected.
  • Late joiners are negotiated in while the existing pairs keep talking.
  • Locking the screen or pressing Back keeps the call alive. Swiping the app from Recents ends it.

Network and TURN

WebRTC first tries a direct path between the phones. On most home Wi-Fi that works. Mobile carriers, CGNAT, and corporate firewalls often block it, and then audio needs a TURN relay to forward the traffic.

Talk2Me ships with STUN but no relay credentials, because there is no free, credential-less TURN service that stays online. You can paste credentials from any provider; they are stored only on the phone.

What a relay does, and does not, see

A TURN server forwards encrypted packets. It can see that two IP addresses are talking and how much data they send, but not the room code, the signaling contents, or the audio.

Using Metered Open Relay (free tier)

  1. Create a free account at dashboard.metered.ca.
  2. Open your project and find the TURN Server or Open Relay credentials.
  3. Copy the username, password, and the turn: / turns: URLs.

If the dashboard only shows an API key, open the credentials endpoint in a browser and copy the values from the JSON it returns: 

https://YOURAPPNAME.metered.live/api/v1/turn/credentials?apiKey=YOUR_API_KEY

Typical Open Relay values look like this:

turn:global.relay.metered.ca:80
turn:global.relay.metered.ca:443
turns:global.relay.metered.ca:443?transport=tcp

In Talk2Me, open Network settings from the home screen and paste: 

TURN URLs: turn:global.relay.metered.ca:80, turn:global.relay.metered.ca:443, turns:global.relay.metered.ca:443?transport=tcp
Username:  <from the dashboard or JSON>
Password:  <from the dashboard or JSON>

Save, then repeat with the exact same values on every phone. The home footer changes to “Network settings · relay on” when a relay is configured.

Metered's current free allowance is around 500 MB per month (check the usage meter in your dashboard). That is roughly 14 hours of relayed 1:1 audio. Group calls relay more paths, so they use it faster.

Old public credentials no longer work

The widely copied openrelayproject username and password are rejected by Metered's current servers. Do not paste them; they will look configured but produce no relay candidates.

Credentials that expire

API-key endpoints issue short-lived credentials. If calls stop relaying after a while, fetch fresh values and paste them again. Static username/password credentials, when your dashboard offers them, do not expire.

Alternative: Xirsys

Xirsys offers a free Developer account with 500 MB/month and static TURN credentials. Create a channel in the dashboard, then copy its username, credential, and turn: URLs into Network settings. After the 30-day trial the account drops to one region, so confirm the credential panel still shows values.

Check the relay before blaming the app

Paste the same URL, username, and password into a TURN tester such as metered.ca/turn-server-testing. If the tester cannot allocate a relay, Talk2Me will not either.

Troubleshooting

The error screen shows “Something went wrong” as its title. The line underneath is the useful part; it identifies which stage failed.

MessageMeaningWhat to try
Could not connect. Try the same Wi-Fi, or add a TURN relay in Network settings. Both phones found each other, but no audio path could be established before the timeout. Retry on the same Wi-Fi. If they are on different networks or mobile data, configure TURN. Make sure both phones have working internet.
Could not start the call audio. Microphone capture or the audio device failed to start. Check microphone permission, close other calling apps, then retry.
Could not start the audio engine. WebRTC failed to initialize on this device. Force-stop and reopen the app. If it persists, reinstall the APK and reboot the phone.
Could not reach the signaling service. All public MQTT brokers were unreachable. Check internet access or try a different network. Retry in a moment.
That call is already full (4 people max). Four people are already in the room. Wait for someone to leave, or start a second room with a new code.
Microphone permission is required to make a call. The mic permission was denied. Grant it in Android Settings → Apps → Talk2Me → Permissions, then retry.
Signal lost — trying to reconnect The connection blipped, for example during a Wi-Fi to mobile handoff. Wait; the app restarts ICE per peer. Persistent trouble usually means the network needs TURN.

Nothing happens after “Found 1 person”

Discovery worked, so signaling is fine. Give it up to 30 seconds on a difficult network, then retry once. If it fails again, the media path is blocked and a TURN relay is the fix.

Collecting logs for a bug report

With USB debugging enabled, this shows the app's own logs plus crashes: 

adb logcat -s "Talk2Me" "Talk2Me/Call" "Talk2Me/Mqtt" "Talk2Me/WebRTC" AndroidRuntime:E

Include your Android version, the phones' network setup (same Wi-Fi, different networks, mobile data), and the exact text under the error title.

Battery and OEM restrictions

During a call, Talk2Me holds a partial CPU wake lock and a Wi-Fi lock, and runs a microphone foreground service. That keeps discovery, negotiation, and audio alive while the screen is locked.

  • Set Talk2Me's battery usage to unrestricted.
  • On MIUI/HyperOS, enable autostart and allow background activity.
  • On Samsung and other aggressive skins, exclude Talk2Me from sleeping apps.
  • Keep the ongoing notification enabled; it is the call's foreground-service anchor.

Pressing Back or locking the screen does not end the call. Swiping the app away from Recents does, because Android stops the service.

Privacy

No account, no analytics, no call records. The public MQTT broker only sees an opaque topic and encrypted SDP/ICE payloads. Audio goes direct between phones, or through your own TURN provider if configured.

Read the full privacy note for what leaves the device and which third parties are involved.

Build from source

You need JDK 17 and Android SDK platform 35. The Gradle wrapper is included, so no system Gradle install is required. 

git clone https://github.com/lawalTheWest/talk2me.git
cd talk2me
export ANDROID_HOME=/path/to/android-sdk
./gradlew assembleDebug
# app/build/outputs/apk/debug/app-debug.apk

Run the tests

./gradlew testDebugUnitTest

Signed release build

Create keystore.properties in the project root. Both it and the keystore are git-ignored: 

storeFile=app/talk2me-release.keystore
storePassword=your-store-password
keyAlias=talk2me
keyPassword=your-key-password
./gradlew assembleRelease
# app/build/outputs/apk/release/app-release.apk (signed, zipaligned)

Back up the keystore and passwords. Losing them means future versions cannot update an installed copy in place.

Verify the APK

The v1.0 release APK is signed with a dedicated key (CN=Talk2Me). Its SHA-256 is: 

02a5f42e1fb66465b8e65e35df1cbcf01c5454d5e8a0d5161fcecf5cfa134425

Compare a downloaded file on Linux or macOS:

sha256sum Talk2Me-v1.0.apk

On Windows PowerShell:

Get-FileHash .\Talk2Me-v1.0.apk -Algorithm SHA256

If you have Android build tools, the signer can be checked too:

apksigner verify --print-certs Talk2Me-v1.0.apk
